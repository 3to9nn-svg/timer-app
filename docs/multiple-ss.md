# 複数SSの使い方

## 更新について

フロントエンド（Vercel）とサーバー（Render）の両方を更新してください。先にサーバーを更新し、その後フロントエンドを更新します。既存の `DATABASE_URL` と `APP_PASSWORD` をそのまま使用し、新しい環境変数や手動のデータベース変更は不要です。

これまでのイベント・計測中の車両・計測結果・出走順は、自動的に「SS1」として読み込みます。タイムやイベント終了日時は変更しません。過去のイベントもSS1として閲覧・CSV保存できます。複数SSのイベントでは旧画面からのSSを指定しない計測操作を拒否するため、担当者全員がページを再読み込みしてください。

## イベントと出走順を準備する

1. 「イベント管理」（旧「エントリー管理」）でイベントを開始し、車両を登録します。エントリーはイベント内の全SSで共通です。
2. 「SS・出走順の事前登録」で、最初のSS名を変更したり、新しいSSを追加します。1イベント最大50SSです。
3. 「設定するSS」を選び、出走順を準備します。
   - **エントリー番号順**：カーナンバーの番号順に作成します。
   - **指定したSSのタイム順**：基準SSの各車両のベストタイムで、速い順または遅い順に作成します。同タイムは番号順、未計測車両は末尾に番号順で並びます。
   - **任意**：ランオーダーへ車両を追加し、上下ボタンで並べます。同じ車両を複数回追加できます。
4. 自動作成は「出走順を作成・再作成」を押した時点の結果を使います。その後基準SSの結果が増えても、登録済みの順番は変わりません。

再作成すると、待機中・スキップ済みの順番を置き換えます。出走済み項目は保持し、その車両は自動再登録しません。再出走させる場合は手動で追加してください。イベント終了後はSS名や出走順も変更できません。

## SSを選んで計測する

スタート・フィニッシュの両担当が「計測するSS」で同じSSを選択してください。この選択は端末ごとに独立しています。

スタート画面で「ラリーセッション」を選ぶと、そのSSに事前登録した出走順を使用します。スタート画面でもスキップ・入れ替え・追加が可能です。スキップした車両は末尾に戻せます。フリーランセッションでは、従来どおり毎回車両を選択します。セッション種別もSSごとに保存されます。

走行中の車両と計測ログは選択中のSSに限定して表示します。他SSで計測中でも、選択したSSの計測を進められます。イベント終了には全SSの走行中車両のフィニッシュまたは取消が必要です。

## リザルトとCSV

「表示するSS・総合」で対象を切り替えます。

- **各SS**：従来の新着順・タイム順・オーバーオールを使用できます。PBとベスト更新の演出はSSごとに判定します。
- **総合リザルト**：各車両の各SSのベストタイムを合計します。全SSを計測した車両のみ順位を付け、未計測SSがある車両は末尾に番号順で表示します。同合計タイムは番号順の連番です。車両を絞り込んでも、総合順位と1位との差は全車両基準を維持します。

SS別CSVは `Result_イベント名_イベント終了日時_SS名_Time.csv`（または `history` / `Overall`）です。総合CSVは `Result_イベント名_イベント終了日時_Total.csv` で、各SSのタイム・合計・順位・1位との差・計測済みSS数を含みます。開催中は終了日時の代わりに「開催中」となります。

管理者CSVはイベント全体の記録を出力し、各結果のSS名も含めます。管理者CSVのファイル名は従来どおり `_history.csv` です。

スマホの総合結果表は横にスクロールして各SSのタイムと合計を確認できます。
