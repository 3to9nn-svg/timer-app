# RALLY TIMING

React + Vite のラリー計測アプリです。Socket.IO を使い、スタート担当・フィニッシュ担当・閲覧者の端末間で車両と計測結果を共有します。

## 起動

```sh
npm install
npm run dev
```

同じ Wi-Fi に接続したスマートフォンで確認する場合：

```sh
npm run dev -- --host 0.0.0.0
```

Vite が表示する Network の URL をスマートフォンで開きます。

## 操作

最初に共有パスワードでログインします。同じタブでは最大12時間ログインを保持します。
画面下部の「ログアウト」で終了できます。

1. 「エントリー管理」でイベント名を入力し、イベントを開始します。
2. 「エントリー管理」で車両番号と車両名を登録します。
3. スタート担当が「スタート計測」でフリーラン／ラリーセッションを選びます。フリーランは毎回車両を選択し、ラリーは登録したランオーダーの順にSTARTを押します。
4. フィニッシュ担当が該当車両の FINISH を押します。
5. 「リザルト」でカーナンバーと名前から車両を絞り込み、タイム順・新着順・オーバーオールを切り替え、表示中の結果をCSV保存できます。
6. 走行中の車両がなくなったらイベントを終了します。記録は残り、次のイベント開始後もリザルトのイベント選択から参照できます。

エントリーの表示順は追加順・カーナンバー順・名前順で切り替えられます。スタートの選択肢は常にカーナンバー順です。
管理者モードではパスワードを再確認し、保存済みイベントのCSV保存・個別削除・全削除を行えます。詳しくは[セッション・管理者モード](docs/sessions-and-admin.md)を参照してください。

タイム順・新着順では各カーナンバーの最速記録に「PB」を表示します。同タイムも対象です。オーバーオールは各カーナンバーの最速1件のみをタイム順で表示し、PB表示を省略します。同タイムが複数ある場合は新しい記録を採用します。
「New」はイベント全体で最後にフィニッシュした1件に付き、次のフィニッシュまたはフィニッシュ時刻から2分経過で消えます。絞り込みやオーバーオールで最新の記録が対象外になった場合、別の記録にNewを付け替えることはありません。
CSV名は `Result_イベント名_YYYY-MM-DD_HH-mm-ss.csv` です。日時はイベント終了時刻（日本時間）を使い、終了前は日時部分が「開催中」になります。ファイル名に使用できない文字は `_` に置き換えます。管理者画面からの保存も同じ命名規則です。

計測取消・車両削除・イベント終了には確認画面が表示されます。通信が切れている間は計測・登録操作を無効にし、再接続時にサーバーのデータを取得します。データベースへの保存完了後に更新を反映します。計測時刻はサーバーが操作を受信した時点で取得します。

## 消えないデータ保存の設定

Render無料プランでも記録を保持するため、サーバー側に外部PostgreSQLの接続文字列 `DATABASE_URL` が必要です。
コード更新だけではデータベースは作成されません。[初回設定とイベントの使い方](docs/event-storage-setup.md) を参照してください。

## 接続先

サーバー側で環境変数 `APP_PASSWORD` の設定と、認証対応サーバーのデプロイが必要です。
パスワードはフロント側には設定しません。フロントとサーバーを両方更新してください。
認証前のデータ配信はサーバー側で拒否します。ブラウザにはパスワードを保存せず、
有効期限付きのセッショントークンを `sessionStorage` に保持します。

既定では既存の Render サーバーに接続します。ローカルのバックエンドを使う場合は `.env.local` に接続先を設定し、Vite を再起動します。

```dotenv
VITE_SOCKET_SERVER_URL=http://localhost:10000
```

スマートフォンからローカルのバックエンドに接続する場合は、`localhost` をバックエンドが動いている PC の LAN アドレスに置き換えてください。

## チェック・ビルド

```sh
npm run lint
npm run build
```

出力先は `dist/` です。表示用のタイムは 1/100 秒単位です。記録の自動削除は行いませんが、保存容量・保持条件は接続先のデータベースサービスに依存します。
